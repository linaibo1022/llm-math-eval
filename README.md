# llm-math-eval

中文数学推理评测的**判分器**：给定题目表和模型输出，用可复现的规则判断答案是否正确，并输出准确率。

它不是通用评测框架，而是把“答案等价判定”这一件事做对的最小实现——这也是配套研究项目 [benchmark-analysis](../benchmark-analysis/) 里“自动判分 vs 人工 rubric”这条分界线的代码侧。

## 特性

- **三阶段判分**：抽取答案 → 规范化 → 等价比较，不直接比字符串
- **等价判定**：`\frac{5}{6}` ≡ `5/6` ≡ `0.8333…`，`3/10` ≡ `0.3`
- **多解顺序无关**：`x=1 或 x=2` ≡ `x=2, x=1`
- **单位与全角容错**：`5 元` ≡ `5`，`＝` ≡ `=`
- **零依赖**：纯标准库（`re` + `fractions`），开箱即用

## 快速开始

```powershell
# 跑评测流水线（读 data/problems.jsonl，输出 results.json）
python run_eval.py

# 跑判分器单元测试
python -m unittest discover -s tests
```

## 判分规则

```
模型输出
   ↓ 抽取（extract_answer）      优先 \boxed{...}，其次“答案是...”，兜底最后一行
   ↓ 规范化（normalize）         去空格/单位/全角符号，统一多解分隔符
   ↓ 比较（is_correct）          字符串相等 → 多解集合相等 → 数值等价（Fraction）
```

| 模型输出 | 标准答案 | 判定 | 走的是哪条路径 |
|---|---|---|---|
| `\boxed{\frac{5}{6}}` | `5/6` | ✅ | 嵌套括号抽取 + 数值等价 |
| `3/10` | `0.3` | ✅ | 数值等价 |
| `x=1 或 x=2` | `x=2, x=1` | ✅ | 多解集合 |
| `5 元` | `5` | ✅ | 单位剥离 |
| `0.8333` | `5/6` | ❌ | 近似值 ≠ 精确值 |

最后一行是刻意设计：**判分器严格区分“精确值”和“近似值”**。模型写出 `0.8333` 说明它知道答案，但这不是严格正确——要不要容忍，是评测设计的选择，不是技术问题。

```

```

## 已知局限

1. 判分只覆盖**数值答案和简单多解**，不含证明题（证明题必须用人工 rubric，见 [benchmark-analysis](../benchmark-analysis/)）。
2. `_to_fraction` 用受限 `eval` 解析算术表达式（`{"__builtins__": {}}` 禁用了内置函数），安全但不要传入不可信输入。
3. 题目只有 8 道，是演示数据，不构成统计结论。

## 测试覆盖

`tests/test_judge.py` 覆盖三类 20 个用例：答案抽取（6）、规范化（4）、等价判断（10）。新增判分规则时，先在测试里加用例再改代码。
